Shamir backups you can check.

slip0039 splits a secret into SLIP-0039 shares: lists of words that you give to people you trust, so that a few of them together can restore the secret. It uses no hidden randomness. The same input gives the same shares, on every machine, so anyone can check that the shares contain the secret and nothing else.

    Deterministic, so you can check it
    
		
    Shamir's secret sharing needs random numbers. The usual implementations, including the reference implementation of SLIP-0039, take them from the operating system. That makes the shares impossible to check. A program with a hidden agenda could put an encrypted copy of your secret in the random parts of the shares, and the shares would look exactly as they should. Only the author of the program could read the hidden copy.
    
		
    slip0039 has no such freedom. Every random value is computed from the encrypted secret and a seed that you provide. Run slip0039 twice on the same input and you get the same shares. Run an independent program on the same input, and if it gives the same shares, the shares contain nothing that the specification does not prescribe.

    Why the EMS cannot be read from the shares
    
		
    The random bytes are a PBKDF2 stream with one iteration, which is HMAC-SHA256 keyed with EMS ‖ SEED. Someone who holds fewer shares than needed sees some of these bytes. Computing the EMS from them is as hard as breaking HMAC-SHA256, unless the key can be guessed.
    
		
    This protection is computational, where truly random shares protect perfectly. It depends on EMS ‖ SEED being impossible to guess. A secret of 128 bits or more is enough on its own. For a short PIN or password, the seed carries the weight: use 64 or more random characters, and keep it secret. The identifier in every share reveals 15 bits of its SHA256 hash.
    
	
    

    


    
	
    
		
    Codecs
    
		
    A share stores a master secret of 16 to 64 bytes. A codec turns the thing you actually want to keep into such a master secret, and back. You choose it with -c, followed by a wordlist and, for some codecs, an argument that you write down with your shares.
    
		
    With most codecs, a wrong passphrase recovers something that looks just as real as the right answer. This is honey encryption: someone who tries passphrases gets a valid looking secret for every one of them, and cannot tell which one is right without trying it where it is used.

    Codecs for numbers, passwords and passphrases use a modular encoding that makes every master secret decode to a secret of the same length. Option --gain bounds how much an attacker can gain from the encoding being very slightly uneven: by default, a factor of at most 1.01.
    
		
    Honey encryption only helps against someone who has no other way to check a guess. The keys of a wallet that has been used can be checked against the blockchain. A PIN, a TOTP secret or the password of an account can only be tried online, a few times, and benefit the most.
    
	
    

    


    
	
    
		
    Examples
    
		
    slip0039 reads the passphrase, the seed and the secret from standard input, one per line. The arguments of split are the iteration exponent, the group threshold and one XofY for every group.
    
	
    

	
    
		
    Split into 2 of 3, recover from shares 1 and 3
    

    $ cat input
TREZOR
qT7vW2mZ9xLp4Rk8sN3cYb6Hd1Jf5Ga0EuViXoPwQeMnBtCzKyAlDgFhIjUrOsS2
bb54aac4b89dc868ba37d9cc21b2cece
$ slip0039 split 0 1 2of3 < input
genius moment academic acid angry device safari evaluate pitch firm screw suitable stadium amount findings garlic tricycle hush scene exceed
genius moment academic agency criminal founder sharp diet identify amuse invasion pants shaft plunge senior jewelry amazing biology detailed retreat
genius moment academic always apart treat snapshot become surface traffic pecan drink credit fiction admit elevator platform package carbon spray

bb54aac4b89dc868ba37d9cc21b2cece
    
		
    Run it on your own machine: you get these very shares.
    
	
    

	
    
		
    Check the shares with verify.py
    

    $ slip0039 split 0 2 2of3 3of5 < input > shares
$ ./verify.py 0 2 2of3 3of5 < input | diff - shares
$ # no output: all 8 shares are identical
    
	
    

	
    
		
    A PIN, and what wrong passphrases give
    

    $ printf '%s\n' 'correct horse' "$SEED" 042195 | slip0039 -c numeric::6 split 0 1 2of3 > pin
$ (echo 'correct horse'; head -2 pin) | slip0039 -c numeric::6
042195
$ (echo 'Correct horse'; head -2 pin) | slip0039 -c numeric::6
702084
$ (echo 'battery staple'; head -2 pin) | slip0039 -c numeric::6
511373
    
		
    Every passphrase gives six digits. Only the bank can tell which one is right, and it blocks the card after three wrong tries.
    
	
    

    


    
	
    
		
    The specification, and its silent change
    
		
    slip0039 implements SLIP-0039, Shamir's Secret-Sharing for Mnemonic Codes, by SatoshiLabs. It passes the official test vectors, and its shares are recovered by the reference implementation.
    
		
    In May 2024 the specification changed, under the same name and number. The 5 bit iteration exponent in every share became a 1 bit extendable backup flag and a 4 bit exponent. When the flag is set, the identifier is no longer part of the salt of the encryption, so more sets of shares can be made later for the same encrypted secret, and the checksum uses the customization string shamir_extendable instead of shamir.
    
		
    The document still has status Final and carries no date or version. Only a footnote mentions a later revision, while its section on versioning says that any enhancement should be standardized as a new BIP or SLIP. Software from before the change rejects the new shares, because their checksum does not match. Shares from before the change remain valid, unless their iteration exponent is 16 or more: then its highest bit now reads as the flag.
    
	
    
	
    
		
    What slip0039 does
    It creates extendable shares by default and recovers both kinds. Option --pre-may-2024 creates shares in the old format, for older software.
    
		
    Both versions included
    The repository contains the current specification, doc/slip-0039.md, and the version from before the change, doc/slip-0039-deprecated.md. See also the history of the document.
    
	
    

    


    
	
    
		
    Get it
    
		
    slip0039 is written in C and has no dependencies. It runs on Linux and macOS. The test suite runs the official test vectors and needs jq; test-verify.sh needs Python 3.
    
	
    

    git clone https://github.com/rsnel/slip0039
cd slip0039
make
./test.sh && ./test-verify.sh
    
	
    
		
    The README describes every option and codec. Option -d shows the internal values, including the EMS and the digests.
    
		
    Test before you trust. Build slip0039 yourself, compare its shares with verify.py, and recover from your shares once before you rely on them. Write down the codec argument, such as the number of words, with the shares.
